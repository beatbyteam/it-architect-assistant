# TOGAF Document Structure Guidance

Целевой архитектурный документ должен иметь фиксированную структуру:

1. Общие сведения
2. Описание бизнес-задач
3. Содержание ИТ-архитектуры
   3.1 Бизнес-архитектура
   3.2 Архитектура данных
   3.3 Архитектура приложений
   3.4 Технологическая архитектура
4. Дополнительные сведения

Правила:
- Разделы верхнего уровня не меняются местами.
- Если данных недостаточно, раздел не удаляется, а получает безопасное описание с явной пометкой дефицита входных сигналов.
- Раздел 3 служит контейнером и должен кратко связывать все архитектурные слои.
- Риски, ограничения, допущения и дальнейшие шаги выносятся в раздел 4.
